# Deployments

The committed network manifests are the source of truth for contract consumers, one per
network:

```txt
packages/contracts/deployments/arc-mainnet.json
packages/contracts/deployments/arc-testnet.json
```

Each runtime serves one network, selected by `NEXT_PUBLIC_ARC_NETWORK` in the
client and `ARC_NETWORK` on the server (`mainnet`, which is what thearcanum.in
runs, or `testnet`, the default when neither is set for development), and reads
only the matching manifest. Set both explicitly when they are configured so they
cannot disagree. A mainnet manifest must carry the broadcast
evidence (`deployedAt` and every `txHashes` entry) or the consumers refuse to start, so a dry-run
manifest with predicted addresses can never bind a mainnet build.

## Manifest contents

A v2 manifest contains:

- identity: `chainId`, `network`, `deployer`, `protocolAdmin`, `oracleSigner`
- deterministic deployment input: `create2Salt`
- indexing boundary: `startBlock`
- token and modules: `usdc`, `policyEngine`, `escalationManager`, `anomalyOracle`,
  `vendorRegistry`, `walletFactory`
- verification evidence: `codeHashes`, `deployedAt`, `compiler`, `evmVersion`, `txHashes`

The Forge deployment writes addresses, principals, salt, start block, and code hashes. After
broadcast, the operator must finalize the manifest:

```bash
cd packages/contracts
node scripts/finalize-manifest.mjs arc-testnet https://rpc.testnet.arc.network
# or, for mainnet:
node scripts/finalize-manifest.mjs arc-mainnet https://rpc.mainnet.arc.io
```

Finalization matches deployment transactions to manifest addresses, checks runtime code hashes
against the RPC, and adds compiler, EVM, timestamp, and transaction metadata. Commit the
finalized file before restarting consumers.

Self-hosted indexers load addresses and `startBlock` from this manifest. A missing `startBlock`
is invalid deployment metadata; consumers must fail rather than silently backfill from genesis.
