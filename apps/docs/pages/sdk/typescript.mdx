# TypeScript SDK

Version `3.0.0` installs from npm as `arcanum-sdk`. It is a direct Arc RPC client that reads
contract state, simulates policy decisions, and signs `executeUSDC` with an agent signer.

```bash
npm install arcanum-sdk viem
```

The write example below is for Arc Testnet development. Keep private keys outside source
control; production operators should use managed signer infrastructure or user-controlled
wallets.

```ts
import { ArcanumClient } from "arcanum-sdk"
import { ARC_TESTNET_RPC_URL, arcTestnet, usdcErc20 } from "arcanum-sdk/chains"
import { privateKeyToAccount } from "viem/accounts"

const arc = new ArcanumClient({
  walletAddress: "0x0000000000000000000000000000000000000001",
  agentSigner: privateKeyToAccount(process.env.AGENT_PRIVATE_KEY as `0x${string}`),
  chain: arcTestnet,
  rpcUrl: process.env.ARC_TESTNET_RPC ?? ARC_TESTNET_RPC_URL,
})

const result = await arc.executeUSDC({
  to: "0x0000000000000000000000000000000000000002",
  amount: usdcErc20(50),
  reason: "OpenAI API top-up",
  metadata: { category: "API" },
})
```

Payment-intent methods use `reference` as the caller's stable business reference. Version 3
replaces the former `idempotencyKey` name; do not send both.
The reference does not make execution idempotent. If receipt waiting times out, retain the
submitted hash and call `confirm(txHash)`; resubmitting can transfer funds twice.

## API

- `executeUSDC({ to, amount, reason, metadata })`
- `createPaymentIntent({ ..., reference })`
- `simulate({ to, amount })`
- `getPolicy()`
- `getDailySpent()`
- `getVendor(address)`
- `onEscalationResolved(escalationId, callback)`
- `onFrozen(callback)`

## Errors

`PolicyDeniedError`, `EscalationRequiredError`, `TransferRevertedError`, `WalletFrozenError`,
`AgentNotAuthorizedError`, and `InsufficientUSDCError` extend `ArcanumError`.
`TransferRevertedError` means the submitted chain transaction reverted; inspect its cause and
transaction hash rather than treating it as a policy denial.
