## 1. Routes, layouts & user flows

Inventory and findings (App Router): routes from `apps/web/app`: `/` (`app/page.tsx` -> `LandingPage`), `/dashboard`, `/dashboard/settings`, `/agents`, `/agents/[walletId]`, `/agents/[walletId]/policy`, `/vendors`, `/ledger`, `/escalations`, `/anomalies`, `/settings`, `/status` (all `(dashboard)` group pages delegating to canvas pages), `/approve/[txHash]`, `/explorer/[wallet]`, `/badge/[wallet]` (public group), `/docs`, `/glossary`, plus `/api/auth/nonce`, `/api/auth/verify`, `/api/auth/session`, `/api/auth/logout`, `/api/trpc/[trpc]`; `not-found.tsx` and group error/loading states. Exact page implementations are consolidated in `apps/web/components/arcanum/canvas/pages.tsx`: DashboardCanvasPage line 1353; Agents 2046; AgentDossier 3701; PolicyEditor 5100; Vendors 5906; Ledger 7249; Escalations 7643; Anomalies 7918; Approval 8164; PublicExplorer 8378; Docs 8751; Settings 9351; Status 9594. These are rich client canvas screens containing their own headers/sections, data tables/cards, forms and interactive dialogs; route wrappers are thin (e.g. `app/(dashboard)/agents/page.tsx` line 4). Dynamic badge is separately implemented in `app/(public)/badge/[wallet]/BadgePublicPage.tsx`: public profile query, wallet identity/governance score/metrics, policy proof and links to `/badge/<wallet>` and `/explorer/<wallet>`, no auth/private secrets. Explorer wrapper decodes wallet and renders PublicExplorerCanvasPage; approval decodes tx hash and renders ApprovalCanvasPage, with loading states.

Layouts/chrome: root `apps/web/app/layout.tsx` loads dark HTML, Inter/Saira Condensed/JetBrains Mono fonts, global/print CSS, metadata, and `Providers` (`app/providers.tsx`). `(public)/layout.tsx` returns children unchanged. `(dashboard)/layout.tsx` wraps in `DashboardPolishLayout`, which provides route transition animation, command palette and keyboard-shortcut overlay (`components/arcanum/DashboardPolishLayout.tsx`). Actual shell is used by canvas/runtime: `components/arcanum/dashboard-shell.tsx` fixed header with HELIX-DAO org button, centered command bar, notification popover (escalation/vendor/indexer notices), `AccountChip`, then `GlobalNav`; floating `?` opens shortcuts. `GlobalNav.tsx` links Dashboard, Agents, Vendors, Ledger, Escalations, Anomalies with active underline. `app/docs/layout.tsx` wraps docs-specific presentation. Glossary has standalone header linking Dashboard and `FOUNDRY VOCABULARY`, two-column term cards (`app/glossary/page.tsx`).

Auth/UI flow: `components/arcanum/WalletAuthBridge.tsx` watches wagmi connection. On connected wallet, first checks `/api/auth/session`; otherwise requests `/api/auth/nonce`, constructs SIWE message (`Sign in to Arcanum Foundry Console`, current host/origin/chain), invokes wallet signature, POSTs message/signature to `/api/auth/verify`, refreshes session, invalidates org query and toast `WALLET AUTHORIZED`. Failed signature shows retry and disconnect actions; disconnect or account disappearance POSTs `/api/auth/logout`, clears published session. `AccountChip`/canvas wallet menu expose connected account state and logout; `ConnectWalletButton` drives wallet connection. API handlers: nonce issues nonce; verify validates SIWE and establishes cookie session; session reads it; logout clears it; tRPC route uses SIWE secret/session protection. Route UI itself gates actions with states such as connect wallet, sign in, owner checks; dashboard is entered by landing CTA and wallet auth is triggered automatically after connect. No separate explicit onboarding wizard found; first-run is connect wallet -> SIWE signature -> org/governed-wallet selection, with empty-state prompts to create/select governed wallet and deploy doctrine.

Landing (`components/arcanum/LandingPage.tsx`) structure in order: `LandingHeader` (logo, GUIDE `/docs`, GitHub, LAUNCH DASHBOARD `/dashboard`), Hero headline “The doctrine layer for agentic wallets on Arc.”, copy about real USDC wallets governed by limits/vendors/anomaly/human escalation; CTAs Launch Dashboard, Read Docs, GitHub; console preview posture 87 FORTIFIED, value governed, active agents, latest decisions. Problem section headline “AI agents move money. Normal wallets give them too much freedom.” with five cards: overspend risk, unapproved vendors, no audit trail, no human approval, no public proof. How Arcanum Works / “The governance loop”: deploy wallet, attach doctrine, approve vendors, agent pays, policy engine, public posture. Product Modules / “Everything an autonomous wallet needs”: GuardedWallet, Doctrine Engine, Vendor Registry, Restraint Queue, Public Explorer & Badge. Why Arc / “Built native to Arc”: USDC-native, EVM-compatible, stablecoin context, fast finality. Inside Console / “Governance at a glance”: dashboard metrics, doctrine editor, restraint queue, public badge/explorer previews. Trust Architecture / “Built for verification, not permission”: non-custodial, open-source, self-hostable, on-chain policy, no fake approvals, human escalation. Final CTA headline “Arcanum turns autonomous wallets into governed economic actors.” with Launch Dashboard and Read Docs. Footer: ARC TESTNET, OPEN PROTOCOL, MIT LICENSE, ARCANUM v0.9.2.

Source path references for route wrappers: `apps/web/app/(dashboard)/*/page.tsx`, `apps/web/app/(dashboard)/agents/[walletId]/policy/page.tsx`, `apps/web/app/(public)/approve/[txHash]/page.tsx`, `apps/web/app/(public)/explorer/[wallet]/page.tsx`, `apps/web/app/(public)/badge/[wallet]/page.tsx`, `apps/web/app/docs/page.tsx`, `apps/web/app/glossary/page.tsx`, and API files under `apps/web/app/api/auth/`.

## 3. UX patterns, data wiring & functional contract

Frontend inventory/data wiring (workspace-relative paths):

STRUCTURE/ROUTES
- Dashboard routes are thin wrappers rendering one canvas page: `app/(dashboard)/{dashboard,agents,agents/[walletId],agents/[walletId]/policy,settings,dashboard/settings,vendors,ledger,escalations,anomalies,status}/page.tsx`; public routes include `app/(public)/explorer/[wallet]`, `badge/[wallet]`, `approve/[txHash]`; docs/glossary are public. All dashboard UI is concentrated in `components/arcanum/canvas/pages.tsx`, whose exports are `DashboardCanvasPage`, `AgentsCanvasPage`, `AgentDossierCanvasPage`, `PolicyEditorCanvasPage`, `VendorsCanvasPage`, `LedgerCanvasPage`, `EscalationsCanvasPage`, `AnomaliesCanvasPage`, `ApprovalCanvasPage`, `PublicExplorerCanvasPage`, `DocsCanvasPage`, `SettingsCanvasPage`, `StatusCanvasPage` (lines 1353, 2046, 3701, 5100, 5906, 7249, 7643, 7918, 8164, 8378, 8751, 9351, 9594).
- Shared shell/layout: `components/arcanum/DashboardPolishLayout.tsx`, `dashboard-shell.tsx`, `GlobalNav.tsx`, `DashboardRouteTransition.tsx`, `dashboard-route-guard.tsx`, `PageMotion.tsx`.
- Other Arcanum components: `AccountChip` (wallet dropdown/copy/explorer/disconnect), `AnimatedNumber`, `ArcanumRuntime` (global context/density/presentation/command/help dialogs), `CommandBar`, `CommandPalette` (live search agents/vendors/pending escalations), `KeyboardShortcuts` (shortcut sheet), `WalletAuthBridge` (SIWE), `LandingPage`, `DocsPage`, `GlossaryTooltip`, `SuccessConfetti`, `canvas/ui.tsx` (canvas primitives), `canvas/loading.tsx` (skeleton loading), `canvas/data.ts` (display constants), `canvas/useCountdownLabel.ts` (expiry countdown). `components/ui` is Radix/shadcn-style primitives: avatar, badge, button, card, command, dialog, dropdown-menu, input, popover, progress, scroll-area, separator, sheet, skeleton, table, tabs, toggle, toggle-group, tooltip.

HOOKS
- `apps/web/hooks/` is empty (no custom hooks there). Hooks are colocated in `lib`/components. `lib/use-reduced-motion.ts` observes prefers-reduced-motion; `use-document-title.ts` manages title; `lib/table-state.ts` normalizes search/matching; `lib/page-state.ts` supports URL `?state=loading|empty|error`; `lib/live-data.ts` defines all live hooks.
- live hooks: `useLiveAgents`, `useLiveLedger`, `useLiveLedgerByWallet`, `useLiveEscalations(status)`, `useLiveAnomalies`, `useLiveVendors`, `useLiveEvents`, `useLiveMembers`, `useLiveOrg`, and dashboard metric hooks (`useLiveDashboardMetrics`). Queries are enabled only after authenticated workspace (`useWorkspaceMode`), retry false, generally 30s stale and window-focus refetch disabled.

STATE/NETWORK
- React local state/useMemo/useEffect; no Redux/Zustand. TanStack Query via tRPC provider is server-cache/state. `lib/trpc.ts` uses `/api/trpc` httpBatchLink; `app/api/trpc/[trpc]/route.ts` serves it. `Providers` (`app/providers.tsx`) composes Wagmi, QueryClient, tRPC, RainbowKit, TooltipProvider, TelemetryProvider, Sonner Toaster.
- Direct tRPC usages (mostly in `canvas/pages.tsx`): agents `list`, `byWalletId`, `policy`, `recordCreatedWallet`, `freeze`, `unfreeze`, `syncSignerState`; ledger `list`, `byWallet`; wallets `list`, `publicProfile`; escalations `list`, `byTxHash`; anomalies `list`, `acknowledge`, `dismiss`; org `listMembers`, `getCurrent`; health `ping`; analytics `postureIndex`, `valueGoverned24h`, `activeAgents`, `threatsBlocked24h`, `pendingEscalations`. `WalletAuthBridge` invalidates org current after auth. `lib/live-data.ts` maps backend records to UI models.
- By page area: dashboard consumes analytics metrics + agents + pending escalations; agents consumes agents list (search/status filtering); agent dossier consumes agent by wallet, wallet ledger, policy; policy editor consumes policy, wallets and signer state and mutates signer sync; vendors consumes vendors list (category/search filters, local vendor policy editing); ledger consumes ledger list (status/search filters); escalations consumes pending list (agent/category/search, expiry sort); anomalies consumes list (ack/dismiss); approval consumes escalation by tx hash; explorer/badge consume public wallet profile; settings uses members/org and wallet lists; status health ping; command palette consumes agents/vendors/escalations.

AUTH/WALLET UX
- `lib/wagmi.ts`: Arc testnet only, RPC `ARC_TESTNET_RPC_URL`, injected connector fallback; if WalletConnect project ID exists uses RainbowKit `getDefaultConfig`, otherwise injected. RainbowKit compact dark theme and Arc initial chain in `app/providers.tsx`.
- `components/connect-wallet-button.tsx`: landing “LAUNCH DASHBOARD”; opens RainbowKit connect modal, connected state routes `/dashboard`, shows shortened address and Disconnect, welcome toast. `dashboard-route-guard.tsx` redirects disconnected users to `/` (development `?preview=1` bypass). `AccountChip.tsx` shows balance/address, copy, Arcscan link, disconnect. Network handling is Arc-testnet config; no explicit chain-switch UX found.
- `WalletAuthBridge.tsx`: when connected, obtains `/api/auth/nonce`, signs SIWE message, POSTs `/api/auth/verify`; success toast “WALLET AUTHORIZED”, invalidates org; failures toast with Disconnect action. Disconnect/logout path. Auth endpoints: GET `/api/auth/nonce` (rate-limited nonce), POST `/api/auth/verify` (schema/SIWE verification, Supabase sync, iron-session cookie), GET `/api/auth/session`, POST `/api/auth/logout`; rate limiter in `app/api/auth/rate-limit.ts`.

UX STATES/INTERACTION
- Loading files exist for every dashboard/public route and `canvas/loading.tsx` renders skeleton rows; query error/empty handling is inline in canvas pages (error retry panels, empty copy, filtered-empty reset guidance). URL page-state helper supports deterministic loading/empty/error previews. Public/dashboard error boundaries at `app/(public)/error.tsx`, `(dashboard)/error.tsx`, docs error.
- Sonner toasts globally themed in providers; used for auth, copy success/failure, disconnect/help, density/presentation toggles, mutations and informational placeholders. Dialogs use Radix `ui/dialog`; sheets use `ui/sheet` for keyboard help; dropdowns for AccountChip; popovers/tooltips for contextual help; notification panel is custom click-outside overlay in dashboard shell. Command palette is keyboard/dialog driven.
- Tables/lists are dense responsive card/table layouts using `ui/table`, scroll areas, skeletons. Client-side filtering is prevalent: agents status + text; vendors category + text; ledger status + text; escalations status/agent/category/search and expiry/newest sort; anomalies list; docs search. Ledger/escalation backend requests use page 0/pageSize 100; no visible pagination controls—effectively capped list. Sorting is client-side. `lib/table-state.ts` only normalizes search/match.
- Forms: policy/vendor/signer forms are controlled local state; USDC fields parsed/validated by `parseUsdcInput`/`parseUsdcCapInput`; signer address validation via viem address checks; touched-state inline validation, disabled/confirmation states, mutation success/error feedback. No form library found.
- Responsive/mobile: Tailwind responsive classes, horizontal overflow/scroll areas for dense tables, compact RainbowKit modal; shell/nav collapse behavior in GlobalNav/DashboardPolishLayout. Motion honors `useReducedMotion`; presentation/density modes alter layout. Accessibility: semantic buttons, aria-label/aria-expanded, dialog/sheet titles/descriptions, tooltip provider, keyboard shortcuts (command palette, help), focus-visible styles, reduced-motion handling.

MOCK VS REAL
- `lib/mock/{agents,anomalies,docs,escalations,events,ledger,members,org,policies,ticker,vendors}.ts` contains fixture datasets, but current live dashboard wiring imports live-data rather than these mocks. Mock files appear fallback/design/demo data. `lib/optimistic.ts` only provides mock network delay. `lib/live-data.ts` is real tRPC/Supabase-backed data, with UI fallback labels/defaults (e.g. owner “Owner synced in Supabase”, zero posture/spend/limits, “No activity yet”, placeholder category/vendor names) when backend lacks fields. Public profile is real tRPC.
